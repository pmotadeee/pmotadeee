## 3. DETALHAMENTO TÉCNICO (COMO FUNCIONARIA)

### 3.1. Fase de Infecção Inicial

- O worm chega numa máquina qualquer.
- **Classificador de hardware** detecta RAM, CPU, etc.:
  ```python
  if ram_gb < 2: funcao = "dendrito"
  elif ram_gb > 34: funcao = "nucleo"
  else: funcao = "node_medio" (faz parte da rede mas não gera payloads)
  ```
- Dependendo da classe, carrega módulos diferentes (mais leves ou mais pesados).

### 3.2. Dendritos (<2GB RAM)

- **Tarefa principal:** escaneamento de rede (ARP sweep, port scanning) e propagação.
- **Comunicação:** usam esteganografia para enviar dados aos núcleos (ex: embedar informações em requisições HTTP legítimas, imagens, ou até em tráfego de voz).
- **Evasão:** como são fracos, não rodam LLMs. Usam técnicas simples de ofuscação (XOR, rotação de IPs) para parecerem tráfego normal.

### 3.3. Núcleos (>34GB RAM)

- **Tarefa principal:** rodar LLMs localmente (ex: Llama 3 8B quantizada) para gerar novos payloads e estratégias.
- **Input:** recebem dados dos dendritos (info sobre alvos, versões de SO, patches).
- **Output:** geram código mutante (em C, PowerShell, etc.) que é distribuído para outros hosts.
- **Auto-evolução:** os payloads gerados são testados e, se funcionam, viram "cepas" virais.

### 3.4. Esteganografia para Bypassar ML

- **Problema:** AVs modernos usam ML para detectar padrões anômalos.
- **Solução:** embutir tráfego malicioso em canais legítimos:
  - DNS tunneling (consultas DNS com dados ocultos em subdomínios).
  - Imagens (LSB steganography) postadas em redes sociais, baixadas pelos núcleos.
  - Tráfego HTTPS mimetizando APIs comuns.
- **Vantagem:** o ML "da Microsoft" é treinado em tráfego normal; se seu tráfego for indistinguível, ele falha.
