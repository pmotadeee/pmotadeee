BLUEPRINT DO EIXO TEMPORAL: SISTEMA DE TELEMETRIA OPERACIONAL PARA GAIOLAS

VISÃO GERAL
O Eixo Temporal é um sistema que transforma eventos discretos (bipagens) em uma linha do tempo contínua da operação. Ele permite medir, analisar e prever o fluxo de gaiolas em tempo real, criando uma camada de observabilidade onde antes só existia caos.

1. COMPONENTES FUNDAMENTAIS
1.1 O MARCADOR DE NASCIMENTO (TIMESTAMP DE INÍCIO)
O que é:
O momento exato em que uma gaiola é bipada pela primeira vez no sistema.

Como funciona:

Quando o operador bipa a primeira saca de uma gaiola, o sistema registra:

ID da gaiola

Chute de origem

Data e hora (timestamp)

Regra fundamental:
Cada gaiola tem um único marcador de nascimento. Depois de registrado, não muda.

Analogia:
É a certidão de nascimento da gaiola no sistema. A partir dela, tudo começa.

1.2 O RELÓGIO UNIVERSAL (HORA ATUAL)
O que é:
O momento presente, continuamente atualizado.

Como funciona:

O sistema consulta o horário atual sempre que precisa calcular algo.

Pode ser o servidor, o PDA, ou uma fonte confiável de tempo.

Função:
Serve como referência para medir quanto tempo já passou desde o nascimento.

1.3 O MEDIDOR DE IDADE (CÁLCULO DE TEMPO DE CICLO)
O que é:

1.4 O AGREGADOR DE FLUXO (MÉTRICAS POR CHUTE)
O que é:
O conjunto de todas as gaiolas que passaram por um determinado chute, com suas respectivas idades.

Como funciona:

O sistema agrupa as gaiolas por chute de origem.

Para cada chute, calcula:

Tempo médio de ciclo = soma das idades / número de gaiolas

Vazão = número de gaiolas / período analisado

Tempo máximo (gargalo identificado)

Analogia:
É como medir a velocidade de cada pista de uma rodovia. Se uma pista está mais lenta que as outras, você sabe onde tem congestionamento.

1.5 O PREVISOR DE FUTURO (ALERTA DE GARGALO)
O que é:
Um mecanismo que compara o tempo médio atual com limites predefinidos e dispara alertas.

Como funciona:

text
SE tempo_médio_do_chute > limite_estabelecido
    ENTÃO chute em alerta
    SENÃO operação normal
Limites podem ser:

Fixos (ex: 2 horas)

Dinâmicos (baseados em histórico)

Comparativos (em relação a outros chutes)

Resultado:
Antes que o congestionamento pare a operação, você já sabe onde intervir.

## 1. FUNDAMENTO TEÓRICO (O QUE É QUANTIZAÇÃO DE ESTADOS DE HILBERT?)

Na tabela, o **ID 13 (Campo de Hilbert Simbólico)** transforma um espaço contínuo de possibilidades (ex: todos os possíveis tempos de ciclo, volumes de pacotes) em um **espaço simbólico fechado** (ex: "baixo", "médio", "alto"). O **ID 15 (Softmax Threshold)** usa limites fixos pra decidir quando um estado vira outro.

**Na fábrica:**
- O espaço contínuo = fluxo de pacotes por destino (número de gaiolas por hora, CEPs, etc.)
- O espaço simbólico = a classificação de cada destino em categorias que determinam em qual chute ele deve cair.

**Objetivo:** Criar um sistema que, depois de uma semana coletando dados, **automaticamente** define os thresholds e atribui cada destino a um chute, equilibrando a carga.

### 2.2. CAMADA 2 – INFERÊNCIA (PROCESSAMENTO E QUANTIZAÇÃO)

#### 2.2.1. Agregação por destino
Para cada destino (RJ, BA, MG, etc.), calcular:
- `volume_total` = soma de volumes no período.

- `fluxo_médio` = volume_total / 7 (média por dia) ou volume_total / horas_ativas.
- `horários_de_pico` (opcional, se quiser refinar).

#### 2.2.2. Definir thresholds (estados de Hilbert)
Com base nos dados, você pode usar percentis para dividir os destinos em, digamos, 3 categorias:

- **Baixo fluxo:** destinos com fluxo abaixo do percentil 33%.
- **Médio fluxo:** entre percentil 33% e 66%.
- **Alto fluxo:** acima do percentil 66%.

**Ou usar thresholds dinâmicos:** por exemplo, se o fluxo médio de um destino for maior que 1.5× a média geral, considera-se "alto".

**Analogia com a tabela:**

- **ID 15 (Softmax Threshold)** – os thresholds são os limites que separam as regiões.

#### 2.2.3. Mapear destinos para chutes
Agora você tem uma lista de destinos com suas categorias de fluxo. O próximo passo é distribuir essas categorias entre os chutes disponíveis, de modo a **equilibrar a carga**.

**Problema de otimização:**  
- Temos N chutes (ex: 8 chutes).  
- Queremos alocar destinos de alto fluxo em chutes diferentes (para não sobrecarregar um único chute).  
- Destinos de médio e baixo fluxo podem ser agrupados.

**Algoritmo simples (em bash ou Python):**
1. Ordene os destinos por fluxo (decrescente).
2. Para cada destino de alto fluxo, atribua ao chute com menos carga acumulada (round-robin ponderado).
3. Repita para médio e baixo.

**Resultado:** Uma tabela de mapeamento: `destino → chute`.

1. FUNDAMENTO TEÓRICO (O QUE É QUANTIZAÇÃO DE ESTADOS DE HILBERT?)
Na tabela, o ID 13 (Campo de Hilbert Simbólico) transforma um espaço contínuo de possibilidades (ex: todos os possíveis tempos de ciclo, volumes de pacotes) em um espaço simbólico fechado (ex: "baixo", "médio", "alto"). O ID 15 (Softmax Threshold) usa limites fixos pra decidir quando um estado vira outro.

Na fábrica:

O espaço contínuo = fluxo de pacotes por destino (número de gaiolas por hora, CEPs, etc.)

O espaço simbólico = a classificação de cada destino em categorias que determinam em qual chute ele deve cair.

Objetivo: Criar um sistema que, depois de uma semana coletando dados, automaticamente define os thresholds e atribui cada destino a um chute, equilibrando a carga.

# 1. Carregar dados da semana

# 2. Agregar por destino

    'volume': 'sum',
    'chute': lambda x: x.mode()[0]  # chute mais frequente (opcional)
}).rename(columns={'volume': 'fluxo_total'})

# 3. Definir thresholds (usando percentis)
fluxos = agregado['fluxo_total']
p33 = np.percentile(fluxos, 33)
p66 = np.percentile(fluxos, 66)

def categoria(fluxo):
    if fluxo <= p33:
        return 'baixo'
    elif fluxo <= p66:
        return 'medio'
    else:
        return 'alto'

agregado['categoria'] = agregado['fluxo_total'].apply(categoria)

# 4. Ordenar por fluxo
agregado = agregado.sort_values('fluxo_total', ascending=False)

# 5. Distribuir nos chutes (ex: 8 chutes)
num_chutes = 8
chutes = {i: {'carga': 0, 'destinos': []} for i in range(1, num_chutes+1)}

for destino, row in agregado.iterrows():
    fluxo = row['fluxo_total']
    # encontrar chute com menor carga acumulada
    chute_escolhido = min(chutes.items(), key=lambda x: x[1]['carga'])[0]
    chutes[chute_escolhido]['carga'] += fluxo
    chutes[chute_escolhido]['destinos'].append(destino)

# 6. Gerar planilha de mapeamento
output = []
for chute, info in chutes.items():
    for destino in info['destinos']:
        output.append({'chute': chute, 'destino': destino, 'categoria': agregado.loc[destino, 'categoria']})

df_output = pd.DataFrame(output)
df_output.to_csv('mapeamento_automatico.csv', index=False)
