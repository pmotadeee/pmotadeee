LABORATÓRIO DE AUTO-REPLICAÇÃO EM REDE ISOLADA — BLUEPRINT TÉCNICO

PARTE I — PRINCÍPIOS DO AMBIENTE

O experimento roda em hardware próprio, rede sem NAT, sem acesso à internet e com snapshot obrigatório antes de cada execução, e isso não é sugestão é requisito técnico porque sem isolamento real o experimento vira crime e sem snapshot a iteração vira impossível.

A rede isolada usa bridge virtual sem uplink físico porque mesmo com firewall bem configurado existe vetor de escape via DNS rebinding e via rota de gateway padrão, então a única garantia real é não ter rota pra fora.

PARTE III — SETUP DO AMBIENTE

3.1 Criação da Bridge Isolada

```bash
# Cria bridge sem uplink
sudo ip link add br-rabids type bridge
sudo ip addr add 192.168.200.1/24 dev br-rabids
sudo ip link set br-rabids up

# Bloqueia forwarding (redundância)
sudo sysctl -w net.ipv4.ip_forward=0

# Regra de firewall para garantir isolamento
sudo iptables -A FORWARD -i br-rabids -o eth0 -j DROP
sudo iptables -A FORWARD -i eth0 -o br-rabids -j DROP
```

3.2 Criação das VMs

Cada VM é uma Debian 12 minimal com qcow2 backing file, o que permite snapshot instantâneo e rollback em segundos.

```bash
# Base comum (uma vez só)
qemu-img create -f qcow2 base-debian.qcow2 8G

# VMs individuais com backing file
for i in 01 02 03 04 05; do
    qemu-img create -f qcow2 -b base-debian.qcow2 -F qcow2 vm-$i.qcow2
done
```

3.3 Script de Boot das VMs

```bash
#!/bin/bash
# boot-vms.sh
for i in 01 02 03 04 05; do
    qemu-system-x86_64 \
        -m 1024 \
        -smp 2 \
        -drive file=vm-$i.qcow2,if=virtio \
        -netdev bridge,id=net0,br=br-rabids \
        -device virtio-net-pci,netdev=net0,mac=52:54:00:00:0$i:01 \
        -nographic \
        -daemonize \
        -pidfile vm-$i.pid
done
```

3.4 Snapshot Antes de Cada Execução

```bash
# Snapshot de todas as VMs antes do experimento
for i in 01 02 03 04 05; do
    qemu-img snapshot -c "pre-run-$(date +%s)" vm-$i.qcow2
done

# Rollback em segundos
qemu-img snapshot -a "pre-run-1234567890" vm-$i.qcow2
```

PARTE IV — DESIGN DO AGENTE DE PESQUISA

4.1 Modelo Matemático de Propagação

O agente se replica seguindo dinâmica SIR-E, e o objetivo do experimento é medir os parâmetros β, μ, ε, não maximizar propagação.

```
dS/dt = -β·S·I/N
dI/dt = β·S·I/N - μ·I + ε·M
dR/dt = μ·I
dM/dt = ε·I - δ·M
```

Onde:

· S(t) = hosts suscetíveis
· I(t) = hosts infectados (agente rodando)
· R(t) = hosts recuperados (agente removido)
· M(t) = hosts com variante mutada
· β = taxa de transmissão (medida)
· μ = taxa de mortalidade (medida)
· ε = taxa de mutação (medida)

4.3 Módulo de Discovery

```python
# discovery.py — roda dentro de cada VM
import socket
import subprocess
import ipaddress


def scan_subnet(subnet: str = "192.168.200.0/24") -> list:
    hosts = []
    net = ipaddress.ip_network(subnet)
    for ip in net.hosts():
        ip_str = str(ip)
        if ip_str == socket.gethostbyname(socket.gethostname()):
            continue
        # ARP ping é mais rápido que ICMP
        result = subprocess.run(
            ["arping", "-c", "1", "-w", "1", ip_str],
            capture_output=True, timeout=3,
        )
        if result.returncode == 0:
            hosts.append(ip_str)
    return hosts


def probe_ports(host: str, ports: list = [22, 8080, 5000]) -> dict:
    open_ports = {}
    for port in ports:
        sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
        sock.settimeout(1)
        try:
            sock.connect((host, port))
            open_ports[port] = True
        except Exception:
            open_ports[port] = False
        finally:
            sock.close()
    return open_ports
```

4.4 Módulo de Replication

```python
# replication.py — replica apenas em VMs preparadas
import paramiko
import base64
import hashlib


# Chave SSH pré-instalada nas VMs alvo (NÃO é exploit, é acesso autorizado)
SSH_KEY = "/etc/rabids/keys/replication.key"


def replicate(host: str, payload_path: str, ssh_user: str = "rabids") -> bool:
    try:
        client = paramiko.SSHClient()
        client.set_missing_host_key_policy(paramiko.AutoAddPolicy())
        client.connect(host, username=ssh_user, key_filename=SSH_KEY, timeout=5)

        # Envia payload
        sftp = client.open_sftp()
        remote_path = f"/tmp/rabids-{hashlib.md5(host.encode()).hexdigest()[:8]}"
        sftp.put(payload_path, remote_path)
        sftp.close()

        # Executa payload em background
        cmd = f"chmod +x {remote_path} && nohup {remote_path} > /dev/null 2>&1 &"
        client.exec_command(cmd)
        client.close()
        return True
    except Exception:
        return False
```

Nota crítica de segurança: a chave SSH é pré-instalada nas VMs antes do experimento começar, e isso é o que diferencia replicação legítima de infecção. Todas as VMs são suas, todas estão configuradas para aceitar o agente, e o experimento mede como o agente se propaga numa rede onde ele já tem permissão pra estar.

4.5 Módulo de Mutation

```python
# mutation.py
import random
import json
import time


PARAMS = {
    "scan_interval": (10, 300),
    "scan_batch_size": (5, 50),
    "replication_delay": (1, 30),
    "mutation_probability": (0.01, 0.2),
}


def mutate(current_params: dict) -> dict:
    new_params = dict(current_params)
    for key, (lo, hi) in PARAMS.items():
        if random.random() < 0.3:
            new_params[key] = random.uniform(lo, hi)
    return new_params


def save_variant(variant: dict, output_dir: str = "/var/rabids/variants"):
    import os
    os.makedirs(output_dir, exist_ok=True)
    path = f"{output_dir}/variant-{int(time.time())}.json"
    with open(path, "w") as f:
        json.dump(variant, f)
    return path
```

5.3 Cálculo dos Parâmetros

Com os dados coletados, calcula-se os parâmetros empíricos da dinâmica SIR-E.

```python
# analyze.py
import json
from pathlib import Path


def compute_beta(events: list, dt: float) -> float:
    """Taxa de transmissão por contato por unidade de tempo."""
    if not events:
        return 0.0
    successful = sum(1 for e in events if e["result"] == "success")
    attempts = len(events)
    return (successful / attempts) / dt


def compute_mu(events: list, dt: float) -> float:
    """Taxa de mortalidade (agentes que param de reportar)."""
    dead = sum(1 for e in events if e["result"] == "dead")
    total = len(events)
    return (dead / total) / dt


def compute_epsilon(events: list, dt: float) -> float:
    """Taxa de mutação (variantes geradas por unidade de tempo)."""
    mutations = sum(1 for e in events if e.get("mutated"))
    total = len(events)
    return (mutations / total) / dt
```

PARTE VII — SEGURANÇA DO EXPERIMENTO

7.1 Kill Switch em Três Camadas

Camada 1 — dentro do agente: cada agente verifica a existência de /tmp/rabids-stop a cada ciclo, e se existir, se auto-encerra.

Camada 2 — no host: script stop-all.sh que se conecta via SSH a todas as VMs e mata processos do agente.

Camada 3 — física: como as VMs rodam em hardware seu, o kill switch final é simplesmente desligar a máquina.

```bash
#!/bin/bash
# stop-all.sh
for ip in $(seq 11 20); do
    ssh rabids@192.168.200.$ip "touch /tmp/rabids-stop" 2>/dev/null &
done
wait
sleep 5
# Verifica que todos pararam
for ip in $(seq 11 20); do
    ssh rabids@192.168.200.$ip "pgrep rabids || echo 'stopped'" 2>/dev/null &
done
wait
```

7.2 Auditoria de Isolamento

Antes de cada execução, roda um teste que verifica que as VMs não conseguem sair da rede.

```bash
#!/bin/bash
# verify-isolation.sh
for ip in $(seq 11 20); do
    result=$(ssh rabids@192.168.200.$ip "curl -m 3 https://google.com 2>&1" 2>/dev/null)
    if echo "$result" | grep -q "Could not resolve\|Network is unreachable"; then
        echo "vm-$ip: ISOLADA ✓"
    else
        echo "vm-$ip: FALHA NO ISOLAMENTO ✗"
        exit 1
    fi
done
```

Se qualquer VM conseguir acessar a internet, o experimento não começa.

PARTE VIII — O QUE ESTE EXPERIMENTO MEDE

O experimento mede quatro coisas que são publicáveis e replicáveis.

Primeira — taxa de propagação real de agente LLM em rede local com permissão pré-existente, o que é o análogo do worm de Toronto mas em escala menor.

Segunda — efeito de mutação de parâmetros no alcance da propagação, o que permite construir paisagem de fitness empírica.

Terceira — viabilidade de detecção via IDS simples (Suricata, Snort) rodando na bridge, o que permite testar hipóteses de defesa.

Quarta — viabilidade de rollback via snapshot após propagação, o que mede recuperabilidade de sistema comprometido.

Nenhuma dessas medidas requer tocar em máquina alheia, e todas são reproduzíveis por qualquer pesquisador com hardware mínimo, e o resultado é ciência aplicada em vez de crime.

PARTE X — SÍNTESE

O experimento é tecnicamente factível em hardware modesto, e o custo é zero porque tudo é local e nada é pago, e a única coisa que precisa ser feita com rigor é o isolamento de rede e o snapshot antes de cada execução.

A diferença entre este experimento e um crime é um único bit: a permissão pré-existente nas VMs. Se todas as VMs são suas, se a chave SSH foi instalada por você, se a rede é isolada no seu hardware, e se o registro é mantido, o experimento é ciência. Se qualquer uma dessas condições falhar, deixa de ser.

A regra é simples: nada de auto-infecção em máquina que não é sua, nada de auto-replicação que atravesse a bridge, e nada de execução sem snapshot. Com essas três regras, o experimento é seguro e reproduzível. Sem elas, é cadeia.
