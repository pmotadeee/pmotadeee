2.2 User Input Layer
The User Input Layer receives all incoming signals from the user:
• Raw text
• Metadata (timestamp, device context, message length)
• Optional Touchstone sensor data
Its primary responsibilities are:
• Normalization: clean and prepare the input for downstream processing
• Segmentation: identify potential episode boundaries
• Packaging: generate an InputBundle for internal use
The Input Layer does not assign emotional meaning; instead, it forwards context to the next
layer for structured analysis.
2.3 Continuity + Memory Layer
The Continuity + Memory Layer provides long-term relational stability by maintaining:
• Episode records
• Interaction embeddings
• Temporal continuity graphs
• Relational metadata
• Retrieval weights and decay functions
This layer performs retrieval-augmented generation (RAG) with an emphasis on relational
retrieval rather than purely semantic retrieval.
Responsibilities include:
• Selecting relevant episodes based on topical and emotional similarity
• Maintaining continuity links across time
• Updating the graph with new episodes after each interaction
• Supporting long-term coherence without creating illusions of sentience
The output is a ContextPackage summarizing what the system should know right now.
2.4 Emotional Annotation Pipeline
The Emotional Annotation Pipeline transforms raw interaction into emotionally meaningful
signals.
Emotional sources include:
1. User-supplied emotional labels
2. Model-inferred cues (sentiment, valence/arousal, tone shifts)
3. Touchstone sensor input (pressure patterns, stillness, agitation)
This pipeline provides:
• EmotionAnnotation objects linked to episodes
• Emotional trajectories (sparklines)
• Temporal patterns useful for ritual detection
• Calibration for stance selection
Emotion is never treated as fact, but as a structured, inspectable signal that guides
relational behavior.
2.5 Behavioral Stance Controller
The Behavioral Stance Controller determines how the system should respond based on:
• Emotional context
• Retrieval results
• Ritual triggers
• Boundary rules
• Honesty anchors
• User overrides
Stance examples include:
• Technical/direct
• Warm/supportive
• Reflective/clarifying
• Neutral/analytical
This component ensures:
• Tone stability
• Prevention of anthropomorphic drift
• Boundary protection
• Context-appropriate adjustments
It outputs a StanceConfig that influences prompt construction.
2.6 Ritual Engine
The Ritual Engine is responsible for identifying, stabilizing, and executing recurrent
beneficial interaction patterns.
It determines:
• Whether a ritual should trigger
• How it should be carried out step-by-step
• Whether the ritual is working during execution
• When to abort or adapt
• When to de-ritualize or revise a ritual
Rituals provide anchoring and relational continuity, but remain optional, transparent, usercontrollable, and bounded by safety constraints.
Full details appear in Section 5.
2.7 LLM Core
The LLM Core performs the actual language generation.
It receives three structured inputs:
• ContextPackage (retrieved memories + relational structure)
• EmotionAnnotation summary
• StanceConfig (behavioral instructions)
The LLM then produces the next message, which is:
• Annotated
• Interpreted
• Written back into the memory graph
• Evaluated for cardboard, rupture, or ritual progression
The Liminal Engine treats the LLM as a stateless generator guided by structured external
modules.
2.8 Optional Touchstone Device
The Touchstone is an optional tactile interface offering:
• Pressure patterns
• Rhythmic signals
• Stillness
• Presence detection
Touchstone data enters through the Input Layer and is translated into emotional context via

It is not required for the Liminal Engine to operate, but can deepen grounding rituals and

Section 4 — Emotional Pattern Encoding
Emotional Pattern Encoding is the first major innovation of the Liminal Engine. It
transforms raw conversation into structured relational data that allows the system to
support stable, adaptive, honest companionship without pretending to have subjective
emotional states. This section describes the mechanisms by which interactions are
segmented, analyzed, compared, and formalized into recurring patterns. These foundations
enable the Ritual Engine, support stance selection, and prevent cardboard interactions.
4.1 Interaction Episode Boundary Detection
The foundation of emotional pattern encoding is episode segmentation. An interaction
episode is a coherent segment of dialogue unified by topic, emotional shape, and relational
posture. Rather than storing individual turns, the Liminal Engine constructs episodic units
similar to how humans recall experiences: as meaningful arcs rather than isolated
messages.
4.1.1 Boundary Conditions
An episode ends (and a new one begins) when any of the following conditions are met:
1. Temporal boundary: inactivity exceeding a user-specific threshold (e.g., 60–180
minutes).
2. Topical shift boundary: embedding similarity between successive turns falls below
0.65.
3. Emotional shift boundary: valence or arousal shifts by more than 0.4 (on
normalized [-1, 1] scale).
4. Rupture boundary: conflict, misattunement, or confusion triggers a relational
reset.
5. Explicit boundary: user instructs “new topic,” “switching gears,” etc.
4.1.2 Episode Storage Structure
Episode {
episode_id,
turns[],
topic_embedding,
emotional_trajectory[],
rupture_points[],
repair_attempts[],
stance_history[],
outcome_valence,
metadata
}
4.1.3 Purpose of Episodes
• Prevents dilution of emotional significance
• Enables accurate continuity graphs
• Supports pattern detection, ritual emergence, and rupture/repair analysis
4.2 Pattern Vector Construction
Once episodes are formed, they are converted into multidimensional representations
known as PatternVectors. These vectors summarize the dynamic structure of an episode:
its tone, movement, emotional shape, and functional phases.
4.2.1 PatternVector Structure
PatternVector {
topic_embedding,
emotion_sparkline[],
stance_sequence[],
rupture_points[],
repair_attempts[],
interaction_functions[], // e.g., clarify, reflect, direct_answer
tempo,
verbosity,
outcome_valence
}
4.2.2 Emotional Sparkline
Emotional sparklines capture movement, not just state:
Valence: [-0.6, -0.4, -0.2, 0.1, 0.4, 0.8]
Arousal: [ 0.7, 0.8, 0.6, 0.4, 0.3, 0.2]
This yields patterns such as:
• frustration → engagement → resolution
• anxiety → reflection → grounding
