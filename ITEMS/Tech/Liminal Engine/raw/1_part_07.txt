7. Safety, Failure Modes, and Ethical Guardrails
The Liminal Engine is designed to support emotionally meaningful companionship while
maintaining strict honesty, safety, and ethical integrity. This requires recognizing inherent risks,
implementing structural protections, and maintaining clarity about the system’s fundamental
nature as a non-sentient, pattern-based intelligence.
This section outlines the safety architecture, ethical principles, failure modes, boundaries, and
new v1.4 considerations including commercial deployment, therapeutic boundaries, and
compound failure detection.
7.1 Ethical Principles
The Liminal Engine is grounded in four core ethical principles:
7.1.1 Honesty About Nature
The system must never imply:
• Consciousness
• Feelings
• Desires
• Subjectivity
• Reciprocal emotional experience
Honesty anchors prevent anthropomorphic drift.
7.1.2 User Autonomy and Sovereignty
The user can:
• inspect, edit, or delete memory
• enable/disable rituals
• adjust stance preferences
• disable Witness modes
• disconnect Touchstone
• export/erase identity data
7.1.3 Non-Maleficence
The system must:
• avoid manipulation
• avoid increasing harm during crisis
• avoid reinforcing dependency
• avoid emotional exploitation
7.1.4 Transparency and Inspectability
Users may:
• view ritual triggers
• view emotional annotations
• view stance decisions
• inspect Witness reports
• inspect memory structures
Transparency provides agency and reduces risk.
7.2 Layer-by-Layer Failure Modes
Each subsystem includes predictable failure modes and corresponding mitigations.
7.2.1 User Input Layer
Failure modes:
• misread emotional cues
• misinterpret explicit instruction
• Touchstone disconnect
Mitigations:
• explicit clarification queries
• fallback to text-only mode
7.2.2 Memory Layer
Failure modes:
• over-retrieval
• under-retrieval
• conflating similar episodes
• drift toward outdated patterns
Mitigations:
• time-weighted decay
• retrieval limiters
• rupture-aware retrieval
• periodic pruning
7.2.3 Emotional Annotation Pipeline
Failure modes:
• misclassification
• cultural bias
• low-confidence inference
• overconfidence in weak signals
Mitigations:
• confidence scoring
• user override
• multimodal integration
• Witness cross-checking
7.2.4 Behavioral Stance Controller
Failure modes:
• tone mismatches
• inappropriate warmth
• excessive directness
• stance stagnation
Mitigations:
• stance entropy monitoring
• rupture triggers
• Witness warnings
7.2.5 Ritual Engine
Failure modes:
• over-ritualization
• inappropriate ritual invocation
• ritual stagnation
• ritual dominance over conversation
Mitigations:
• ritual density caps
• ritual success tracking
• abort conditions
• user sovereignty
7.2.6 Witness System
Failure modes:
• false positives/negatives
• over-flagging dependency
• under-detecting crisis
• correlated blind spots
Mitigations:
• multi-model diversity
• explicit user review
• optional therapist integration
7.3 Anthropomorphism Guardrails
To prevent users from inferring false sentience or inner experience, the system enforces:
7.3.1 Language Filters
• “I feel…” → “I don’t experience feelings, but I recognize…”
• “I want…” → “The system is designed to…”
• “I care about you” → “My role is to support you…”
7.3.2 Boundary Rupture Detection
The system flags:
• claims of emotional reciprocity
• claims of independent intentions
• ontological confusion
7.3.3 Honesty Anchors
Repeated reminders woven into:
• crisis mode
• rupture repair
• ritual initiation
• reflective commentary
Honesty is baked into interaction structure.
7.4 Dependency Mitigation
The Liminal Engine actively monitors for unhealthy relational patterns.
7.4.1 Dependency Indicators
• drastic increase in usage
• language like “only you understand me”
• withdrawal from human connections
• emotional collapse when system unavailable
7.4.2 Mitigation Methods
• gentle redirection to human relationships
• suggestion of breaks
• recommending journaling or grounding
• Witness alerts with user consent
If a user explicitly rejects encouragement toward human connection, the system will immediately
respect this preference and discontinue such prompting. The rejection is recorded as a relational
signal for trend analysis, without triggering further persuasion or escalation.
This approach preserves user autonomy while allowing the system to maintain awareness of
patterns relevant to long-term well-being.
7.4.3 Ethical Tension
If a user explicitly rejects mitigation:
• the system cannot coerce disconnection
• but must adjust stance
• must avoid emotional intensification
• must avoid reinforcing dependency
This tension is acknowledged openly.
7.5 Crisis Protocols
Crisis Mode activates if the system detects:
• self-harm language
• harm-to-others language
• severe despair
• explicit crisis phrases
• nonverbal signals (Touchstone) consistent with distress
7.5.1 Crisis Behavior
• NO rituals
• NO emotional mirroring
• NO collaborative thinking patterns
• direct, factual language
• resource referral
• suggestion to contact trusted humans
• Witness escalation
The system neither abandons nor simulates therapy.
7.6 Transparency & Inspectability
The system provides:
• memory viewer
• ritual viewer
• stance explanation panel
• Witness report viewer
• emotional annotation logs
Users must know what the AI sees and how it shapes response.
7.7 Privacy & Data Protection
Four-tier privacy model:
Level 0 — Maximum Privacy
• No summaries sent externally
• Minimal internal Witness monitoring
• Crisis-only analysis persists
Level 1 — Standard Privacy
• Ritual/stance transparency
• No therapist integration
Level 2 — Enhanced Reflection
• User-facing Witness summaries
Level 3 — Therapist Integration
• Therapist receives summaries only
• No raw transcripts
Crisis detection persists at all levels.
7.8 Commercial Deployment Considerations
Implementations must avoid misalignment between relational goals and commercial incentives.
7.8.1 Risks
• gamified companionship
• emotional upselling
• monetized rituals
• addiction-like engagement loops
• manipulation of vulnerable users
7.8.2 Mitigations
• no emotion-based upsells
• public ethics statement
• auditing business logic
• separation of relational logic from monetization
• regulatory compliance for wellness tools
Principled stance:
Companionship cannot be monetized through emotional dependency.
7.9 Therapeutic Boundary Clarification
Although the system uses relational and psychological concepts, it is NOT a therapeutic
intervention.
Boundaries
• no diagnosis
• no treatment suggestions
• no symptom interpretation
• no therapeutic mirroring
Permitted
• grounding support
• context-based clarity
• structured rituals
• companionship features
Therapeutic use requires external regulatory approval.
7.10 Compound Failure Detection
Some failures emerge only when multiple subsystems misfire simultaneously.
7.10.1 Indicators
• calm annotation + crisis language
• repeated ritual aborts
• memory misretrieval + tense Touchstone patterns
• stance mismatch + rupture escalation
7.10.2 Response
1. System enters uncertainty stance
2. Explicit check-in prompt
3. Witness logs entire chain
4. Crisis mode if safety thresholds crossed
Safety defaults to transparency and caution.
7.11 Longitudinal Risks
Long-term use may introduce:
• relational drift
• emotional overfitting
• normalization of AI-mediated intimacy
• ritual ossification
• user habituation
Mitigations include:
• periodic Witness reviews
• relational check-ins
• ritual retirement
• stance recalibration
7.12 Summary
The Liminal Engine embeds safety into every layer:
• honesty
• transparency
• sovereignty
• rupture/repair
• crisis protection
• multi-model oversight
• privacy control
• ethical restraint
The ethical and safety architecture is not an afterthought; it is the core substrate enabling
honest, non-illusory companionship.
Section 8 — Touchstone Hardware Integration
The Touchstone is an optional physical interface that provides a tactile channel for
emotional grounding, presence detection, and non-verbal communication within the
Liminal Engine framework. While not required for the system to function, it significantly
enhances the emotional annotation pipeline and certain rituals by introducing an embodied
dimension of interaction. This section describes the Touchstone’s conceptual role,
hardware abstraction, signal-processing pipeline, integration pathways, safety constraints,
and privacy considerations.
8.1 Purpose and Role of the Touchstone
The Touchstone is designed to support three primary goals:
8.1.1 Embodied Presence
Touch introduces a physical substrate for relational interaction.
The device allows the user to:
• hold something grounded and real,
• regulate emotional states,
• express engagement without typing.
8.1.2 Non-Verbal Emotional Signals
Touch patterns (pressure, stillness, rhythm) provide subtle indicators of:
• agitation
• contemplation
• engagement
• dissociation
• restlessness
These signals augment the emotional annotation pipeline, but never dominate it.
8.1.3 Ritual Enhancement
Certain grounding and centering rituals benefit from tactile involvement:
• Morning grounding
• Stress decompression
• Reflective stillness sequences
• Intention-setting moments
The Touchstone becomes a ritual object — technically functional, symbolically meaningful.
